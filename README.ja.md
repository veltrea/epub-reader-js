# EPUB リーダー

日本語の本を読むための macOS 向け電子書籍リーダーです。本文の表示と組版に **foliate-js**、
アプリの外側（窓・メニュー・ファイルの読み書き）に **Rust/Tauri** を使っています。
日本語の**縦書き**と**右から左へのページ送り**を、文字が画面からはみ出さない形で表示します。
**VOICEVOX / AivisSpeech** を使って本文を読み上げます。

English: [README.md](README.md)

> **状態**: バージョン 0.4.0、macOS と Windows。どちらも実機で動かして画面を確かめ、
> 自動の検査も通していますが、**大勢に配って試してもらった段階ではありません。**
> **Windows 版は macOS 版より確認が浅い**です（下の「できていないこと」に書いてあります）。
> [できていないこと](#できていないこと)を参照してください。

## なぜ作ったか

多くのリーダーは、日本語の縦書きを後回しにしています。実際に何が起きるかというと、
**縦書きの本を開くと、本文が画面の左右にはみ出します。** はみ出した文字は画面の外にあって
見えません。しかも**横にスクロールできないので、そこへ行く方法がありません。**
つまり、**続きが読めないまま止まります。** 本文が全部そこにあるのに、読めません。

このアプリが使っている foliate-js は、そもそもはみ出しようがない作りです。
**1 ページに入る量を先に決めてから、文字を流し込みます**（CSS の段組みの機能を使います）。
入り切らなかった文字は、画面の外へ押し出されるのではなく、**次のページへ回ります。**
縦書きでも横書きでも同じです。

想定している使い方は**自分の原稿の下見**です。読者に見えるとおりに EPUB を見ます。
本のデータが壊れていたり変わっていたりするときは、不備を知らせるより**無難に表示する**ほうを選びます。

## できること

**書棚**
- 取り込み: ファイル単体 / フォルダごと（再帰）/ ウィンドウへのドラッグ&ドロップ / Finder でダブルクリック
- 書棚を複数に分ける（蔵書ごと独立）、入れ子にできる分類、お気に入り
- 作者の読みによる五十音分類（読みは手で直せる）
- 並び替え（最近・タイトル・作者・出版社）、項目を指定したフィルタ、表紙サムネイル（無い本には代替表紙）

**リーダー**
- 縦書き / 横書き / 右綴じ・左綴じを自動で見分けます。本が「縦書き」と名乗っているかどうかだけでなく、
  **実際にどう組まれているか**を見て決めます
- 目次、進捗スライダー（右綴じの本では左右を反転）、しおり、本文の全文検索
- ページ送り: ボタン / 矢印キー / マウスホイール / 画面の左右端をクリック
- 文字サイズ、行間、余白の強制、テーマ（ライト / セピア / ダーク）
- カスタム CSS（全体・本ごとの2層）
- 固定レイアウト（FXL）の見開き、見開きずらし（ページの組が合わない写真集の補正）
- 画像だけの面（表紙・口絵）は版面いっぱいに描く
- 自動ページ送り

**読み上げ**
- VOICEVOX / AivisSpeech。話者・話速・無音長を指定できる
- 文単位のハイライトと、文の中の進行を示すカラオケ式の塗り
- 章を跨いで読み続ける / 選択した箇所から読む / ルビは読まない
- **読み上げ辞書**: 固有名詞の誤読を直す。表記→読み（かな）を優先度つきで登録（語・パターン）
- いま開いている章を音声として、または本文を出した動画として書き出す
- スリープタイマー（読み上げを止め、続けてパソコンをスリープ／シャットダウンも選べる）

**そのほか**
- 日本語 / 英語（macOS のネイティブメニューバーも同じ設定に追従。訳文の出所は1つで、
  Rust 側も同じ JSON を読む）
- 対訳ペイン（任意）。OpenAI 互換の API で訳して原文の横に並べる。手元のサーバー
  （LM Studio など）でも、API キーを入れればクラウドのサービスでも

## 対応形式

| 形式 | 状態 |
|---|---|
| EPUB 2 / 3（リフロー・固定レイアウト） | 本命。検証済み |
| CBZ・FB2・FBZ | 検証済み（取り込み・メタデータ・表紙・閲覧） |
| AZW3・KF8 | 検証済み（取り込み・閲覧。縦書きもそのまま出る） |
| MOBI・AZW | 検証済み（取り込み・閲覧）。ただし**縦書きの本でも横書きで出ます**——古い MOBI 形式が縦書きの指定を持たないためです。ツールバーの縦横ボタンで縦書きに直せます |

この表に無い形式は受け付けません。ウィンドウへドロップしても何も起きませんし、
ファイル選択のダイアログにも出てきません。

## 必要なもの

- macOS（Apple Silicon / Intel）または Windows 11（64 ビット）。
  Windows では **WebView2** が要りますが、Windows 11 には最初から入っています。
  Linux 版はありません。
- 読み上げに: [VOICEVOX](https://voicevox.hiroshiba.jp/)（`:50021`）または
  [AivisSpeech](https://aivis-project.com/)（`:10101`）をローカルで起動しておく。
  どちらも同梱していないので各自で導入してください。
- 翻訳に（任意）: OpenAI 互換の API。手元で動かすサーバー（[LM Studio](https://lmstudio.ai/) や
  [Ollama](https://ollama.com/)）なら本文は外に出ません。設定に API キーを入れれば
  クラウドのサービスにも繋げます（その場合は本文が送られます）。

**音声のライセンス**: これらのエンジンが作った音声には、**使った音声ライブラリごとの規約**が
付いてきます。多くはキャラクター名のクレジット表記を求めています。書き出した音声や動画を
公開する前に、使った声の規約を確認してください。

## 導入

### Windows

インストーラ（`.exe` または `.msi`）をダウンロードして実行してください。

**初回だけ「Windows によって PC が保護されました」という青い画面が出ます。**
署名の証明書を取っていないためで、危険という意味ではありません。
**「詳細情報」を押すと「実行」のボタンが出る**ので、それで進めてください。

### macOS

公証（notarize）済みの配布物はありません（Apple Developer ID を取っていないため）。
自分でビルドするか、ad-hoc 署名のリリースを使ってください。

```bash
# 前提: Rust (1.77+) と Tauri CLI
cargo install tauri-cli --version '^2'

git clone https://github.com/veltrea/epub-reader-js
cd epub-reader-js/src-tauri
cargo tauri build --bundles app
# → src-tauri/target/release/bundle/macos/epub-reader.app
```

自分でビルドしたものには quarantine 属性が付かないので、そのまま開けます。

`.dmg` / `.zip` をダウンロードして使う場合、macOS が初回に拒否します（「開発元を検証できないため
開けません」）。macOS 15 以降は「右クリック→開く」が無くなっているので、
**システム設定 → プライバシーとセキュリティ → このまま開く**を使うか、属性を自分で外してください:

```bash
xattr -dr com.apple.quarantine /Applications/epub-reader.app
```

配布物を作るには（2 つの OS 分）:

```bash
./scripts/package-macos.sh               # macOS → dist/epub-reader-<版>-macos.{dmg,zip}
./scripts/xbuild-windows.sh --installer  # Windows → dist/windows/*.{exe,msi}
```

**Windows の分は Windows 機でビルドされます。** macOS ではビルドできません。

## 開発

```bash
cd src-tauri && cargo tauri dev    # フロントはそのまま配信。JS/CSS はビルド不要

node tests/logic.test.mjs          # DOM 非依存のロジックテスト
cd src-tauri && cargo test --lib   # Rust のユニットテスト
```

フロントはバンドラ無しの素の ESM で、`src/` をそのまま Tauri の `frontendDist` として配信します。
組版・表示・読み上げ制御はフロント側、Rust は永続化・ファイル I/O・HTTP プロキシに徹します
（TTS エンジンは CORS を避けるため Rust 経由で呼びます）。純粋にできるロジック——かな処理・
読み上げ辞書・タイマー——は DOM 非依存に切り出して Node でテストします。

構成と内蔵テストバスの詳細は [docs/DEVELOPMENT.ja.md](docs/DEVELOPMENT.ja.md)。

## できていないこと

- **Linux 版はありません。**
- **Windows 版で、まだ確かめていないことがあります。**
  - **ドラッグ&ドロップで本を取り込むところ**を、実際に落として見ていません
    （仕組みとしては OS の差を吸収する作りになっています）。
  - **ファイルを選ぶ窓とフォルダを選ぶ窓**が出るところを見ていません。
  - **スリープとシャットダウン**（読み上げのタイマーが終わったときの動作）を
    実際に動かしていません。コードは書いてあります。
  - **読み上げエンジンの起動**は、エンジンを入れた機械で試していません。
  - 見た目の作法が macOS のままです。**アプリ名のメニューが「ファイル」の左**にあり、
    Windows の普通の並びとは違います。
- **MOBI・AZW は縦書きで出せません。** 古い MOBI 形式には縦書きの指定を入れる場所が無いので、
  縦書きの本を変換しても横書きになります。ツールバーの縦横ボタンで縦書きに直せます。
  AZW3・KF8 なら縦書きのまま出ます。
- 大きい固定レイアウト本の取り込みは、表紙を取り出すのに数十秒かかることがあります。
  進捗は出しますが、待ち時間は実際にあります。
- 見開きずらしは手動です（自動判定はまだありません）。
- 対訳ペインは動きますが、見た目だけが他の画面に揃っていません。
- 対訳の質は、繋いだモデルがそのまま出ます。アプリは訳を作らず並べるだけです。小さいモデルは
  会話・敬語・固有名詞で崩れ、人名を作ることもあります。**読めない言語へ訳したものは、
  そのままでは正しさを確かめられません。**
